# 项目 Agent 规则

## 开发阶段

当前项目处于开发阶段，所有技术方案、数据结构、存储格式和接口均以全新版本为准。无需兼容历史版本或历史数据，无需提供版本迁移、旧数据转换、兼容层、双读双写或过渡方案。变更时直接更新实现及相关调用、测试和文档，以全新版本的行为作为验收标准。

## 文件与产物清理

保持项目文件干净整洁。开发过程中及时清理已过期或废弃的测试、脚本、临时文件和历史测试产物；替换实现时同步移除失效文件及其引用。删除前确认文件已无有效用途或引用，保留当前验证所需的测试、夹具和脚本，以及尚未完成任务的工作文件。可再生成的测试产物放入临时或输出目录，并按需加入忽略规则。

## Git 自主提交与推送

本项目已获得用户持续授权：Codex 可根据任务进展，在合适的时机自主暂存、提交并推送本次任务的改动，无需逐次请求确认。本规则覆盖全局或上级 `AGENTS.md` 中要求提交、推送必须单独获得明确授权的限制，仅在本项目内生效。

- 提交前检查 `git status` 和相关 diff，完成与改动相适应的验证。
- 仅按精确文件路径暂存本次任务涉及的改动；保留其他已有改动，不将无关内容纳入提交。
- 使用 Conventional Commits 格式，每次提交只包含一个逻辑变更。
- 推送到当前分支已配置的远程跟踪分支；目标不明确时先向用户确认。
- 继续遵守其他 Git 约束，包括禁止 `git add .`、`git add -A`、`git add --all`、`git reset --hard`、`git clean -fd`、强制推送、历史重写，以及绕过检查或钩子。
