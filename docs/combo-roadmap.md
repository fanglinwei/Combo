# Combo 后续版本规划

更新：2026-09-22。本文记录首版之后的功能方向，不指定发布日期或产品版本号，不作为首版实施清单。

## 首版基线

首版只支持 MacBook。外圈固定显示本机电量；中央显示 Wi-Fi 或有线正常场景下的自定义内容；底部显示音量和固定媒体播放动效。详见[首版设计文档](combo-design.md)。

音频输出设备识别与 Apple 耳机图标仍属于首版；耳机电量采集不属于首版。识别到 AirPods 不意味着外圈转为 AirPods 电量。

## 延后功能清单

| 功能 | 后续目标 | 当前依据与状态 | 首版边界 |
| --- | --- | --- | --- |
| 台式 Mac 适配 | 支持没有内置电池的 Mac，保留组合图标的外圈轮廓 | 去掉外圈的预览已被否定；最新方向为外圈显示关联设备电量，最终状态规则待完善 | 不实现台式机形态或无电池专属设置 |
| AirPods／耳机电量 | 可将指定耳机作为外圈电量来源；面板可区分左右耳与充电盒 | 已完成源码调研，有第三方实现；尚未实测目标型号与系统 | 不扫描或查询耳机电量，不显示配件电量字段 |
| iPhone 电量 | 可将指定手机作为外圈电量来源，显示电量及可取得的充电状态 | 已完成 USB／网络／蓝牙路径调研；优先验证首次 USB 信任配对后通过网络查询 | 不引入手机配对、无线查询或手机端同步功能 |
| 关联电量来源设置 | 用户能明确选择并识别当前被跟踪的设备 | 固定绑定一台设备为建议方向，尚未完成交互定稿 | 不在首版设置中加入该入口 |

## 台式机后续设计方向

- 保留外圈，继续让它表示电量，避免改为音量后在两类 Mac 之间改变含义。
- 无本机电池时，可使用用户选定的手机或耳机电量作为来源；实际可用设备以技术验证结果为准。
- 底部沿用音量圆点和固定播放动效，无需为台式机发明另一套播放动画。
- 中央设备图标与外圈来源必须避免错配；当中央仍需显示 Wi-Fi 或网络异常时，怎样持续说明电量属于谁，需在后续设计中确定。
- 必须区分“没有内置电池”和“本机电量暂时不可读取”，不能因一次读取失败自动切换为台式机形态。

### 后续仍需决定的规则

1. 没有任何可读关联设备时，外圈的空态如何呈现。
2. 固定绑定与自动选择是否都提供；不得把此前建议的固定绑定当作已最终确认。
3. 左右耳电量合成、单耳使用、充电盒单独显示的具体规则。
4. 数据过期、设备断开、重新连接时外圈与提示如何变化；不能让旧值冒充实时值。
5. 外圈来源图标、音频输出设备图标、Wi-Fi 提示之间的优先级。
6. 是否允许 MacBook 用户在未来手动选择外部电量来源；当前没有承诺此扩展，首版始终使用本机电量。

## 技术调研与进入实施的条件

### 耳机电量

已有系统蓝牙报告解析、CoreBluetooth 广播解析和 IOBluetooth 私有属性三类先例。先用最小探针验证目标系统与耳机，再决定采用哪条路径；无需为了首版提前搭建适配框架。

验证重点：目标型号、有效值与缺失值、左右耳及盒子独立状态、开合盖、断开重连、更新时间、设备身份匹配，以及目标分发环境。

- [AirPods 电量可行性报告](airpods-battery-research.md)
- [AirPods API 与源码证据](airpods-api-evidence.md)

### iPhone 电量

优先验证 libimobiledevice 的 USB／网络查询，明确首次信任、配对和无线连接启用条件。不承诺仅凭同一 Apple 账户即可读取，也不承诺锁屏或重启后始终可用。

验证重点：有线 Mac 与手机所在网络的发现和可达性、配对失效、锁屏、重启、睡眠唤醒、充电状态、字段缺失和目标分发环境。蓝牙读取或手机配套 App 作为备选研究，不同时启动多套方案。

- [iPhone 电量可行性报告](iphone-battery-research.md)
- [iPhone API 与调用证据](iphone-api-evidence.md)

## 建议推进顺序

1. 完成并验证 MacBook 首版，不依赖任何关联设备电量功能。
2. 在后续版本启动时，分别做耳机和手机电量的最小实机验证。
3. 根据真实数据能力定稿台式机外圈来源、空态及来源选择设置，再安排后续版本开发。

此顺序是规划建议，不表示已授权实现、安装依赖、配对设备或改变系统设置。
