# Combo 系统菜单整合：方案对照与实施计划

更新于 2026-09-23。**当前版本改为手动三合一：用户在 macOS“系统设置 → 菜单栏”亲自隐藏 Wi‑Fi、声音、电池，Combo 提供状态与操作入口；私有折叠实验仍禁用。**设置页尝试记录三项原始状态、辅助检测设置值，并在正常退出时恢复；异常退出或授权失效时可能需要用户手动恢复。Wi‑Fi 选网采用 CoreWLAN，声音输出采用 Core Audio；低电量模式、耗电应用及 AirPods 高级操作交给系统界面。下面的自动折叠方案对照保留为历史研究，不是当前版本承诺。[macOS 27 备用路径调研](macos27-menu-folding-research.md)、[系统设置手动隐藏调研](menu-bar-hiding-research.md)。

## 目标与已确认的产品行为

- 从 macOS 27 开始支持这一功能。第一轮只处理 Wi‑Fi、声音／AirPods、电池；日期／时钟单独验证，不纳入首轮承诺。
- 只折叠这三项系统图标。Combo 自身图标、控制中心、时钟、蓝牙和所有第三方图标必须保持可见；若无法持续确认 Combo 图标可见，立即释放全部 Combo 折叠限制并标记功能不可用。
- “整合系统菜单”总开关默认关闭。Wi‑Fi、声音／AirPods、电池初始选中，但每项可以独立取消；未选项必须保持可见。关闭总开关应恢复已折叠项，并保留用户的选择。
- 点击 Combo 打开面板，再选择对应入口。Combo 可以短暂显示原系统图标，打开**真正的系统菜单**，待菜单关闭后重新折叠。不得用自绘面板冒充 Wi‑Fi 选网、AirPods 降噪／空间音频或电池菜单。
- 某一项无法唯一识别、折叠或稳定打开原生菜单时，该项保持可见；其他已验证项可以继续工作。不能只凭用户勾选或辅助功能已授权就显示“折叠成功”。
- Combo 需要辅助功能权限来定位、移动或操作菜单项。优先验证无需屏幕录制的路径。检测到 Bartender 等菜单栏管理器正在管理同一布局时，提示用户先退出它，再启用 Combo 折叠；Combo 不代用户结束该应用。

## 四种方案对照

| 方案 | 折叠方式 | 三项独立选择 | Combo 内打开原生菜单 | 结论 |
| --- | --- | --- | --- | --- |
| **Thaw 式分区与临时展开** | 使用自身的 `NSStatusItem` 分隔区；识别系统项后以 Command 拖动放入隐藏区，长分隔项将其移出可见范围 | 机制上可逐项移动；本机 CGS 只返回整块菜单栏窗口 | 临时移回可见区，点击实时目标，菜单结束后拖回；尚未在本机验证 | 本机没有逐项窗口身份，当前不执行这种拖拽 |
| **MenuBarClientCore 私有白名单** | 激活系统菜单项允许列表，把指定系统 ID 排除 | 理论上可以，但 ID 和行为均不受公开契约保证 | 需要暂时释放限制、确认目标可见并唤起菜单，再重新限制；已有项目报告点击可能被限制拦截 | **暂停**。本机只排除 Wi‑Fi 时 Combo 也从菜单栏辅助功能树消失 |
| **Ice 式公开 spacer + 系统 overflow** | 扩展 Combo 自己的窄状态项，把其左侧项目推入 macOS 的 `«` 溢出区 | **不能自动按三个开关精确选择**；依赖用户手动摆放系统图标 | 可经系统 overflow 操作，Combo 的逐项原生菜单入口还需另行验证 | 不满足当前三个指定图标独立开关的需求 |
| **系统设置手动隐藏** | 用户在 macOS 设置中关闭对应状态项显示 | 本机已验证可逐项隐藏，Combo 和另两项仍在 | 原菜单栏图标已不在，通常需通过控制中心／系统设置操作 | **人工兜底**；隐藏状态持久化，Combo 崩溃后不会自动恢复 |

Thaw 的[公开源码](thaw-menu-folding-research.md)证明了分区、识别、移动、临时展开的实现链路，但其 **macOS 27 的 `thaw-next` 源码是私有的**。不能据公开的 macOS 26 代码宣称该链路已在 macOS 27 可用。Ice 和 MenuBarClientCore 的证据、实验 ID 与限制见[备用路径调研](macos27-menu-folding-research.md)。Thaw 为 GPL-3.0；在分发许可未决定前，只参考机制与事实，Combo 不直接移植其源码。

## 当前实测与权限边界

此 worktree 的 Combo.app 已重新加入辅助功能列表并获得授权；ad-hoc 重新签名后仍需重新授权。应用内只读检测查询 `com.apple.controlcenter` 和 `com.apple.systemuiserver` 的 `AXMenuBar`、`AXExtrasMenuBar`，四个根属性均返回 `-25212`（`kAXErrorNoValue`）。改从 `MenuBarAgent` 根节点定向扫描后，Combo 找到三项 ID 的候选，并读到点击动作与位置属性。扫描找到首项即停止，尚未证明多显示器下的唯一性或实际可见。短时限制让目标项从辅助功能树中消失，尚缺屏幕像素的视觉证据。

较早的 macOS 26 SDK CLI 探针通过编译和参数保护检查，但执行进程当时未获辅助功能权限；它不能证明原生菜单或折叠可用。该历史探针已清理，应用内当前检测位于 `Combo/MenuBar/MenuDiagnostics.swift`。旧的“先在 Control Center 根项找三个标识，再 AXPress”的顺序已被上述 macOS 27 结果取代。

## 推荐实施顺序

1. **只读识别。** 在已授权的 Combo GUI 进程里沿 `MenuBarAgent` 的菜单栏容器定位 Wi‑Fi、声音、电池，分别取得唯一身份、几何位置及可执行操作。当前不做 CGS 窗口拖动。
2. **稳定签名与安全前提。** 使用稳定签名的 Combo.app，先证实自身图标在限制期间持续可见，并证实三项之外的系统及第三方图标不受影响。当前白名单仅包含启动瞬间运行的应用，不能保证后续启动的第三方图标继续可见；正式启用前必须解决。任一条件不成立就释放限制并停用功能。
3. **单项可逆实验。** 排除一个已定位的系统 ID，核实它确实消失、其他图标不受影响，8 秒自动解除并核实恢复。任一步失败就保持该项可见。
4. **原生菜单闭环。** 从 Combo 面板临时露出该项，确认系统菜单真实打开；以菜单消失和目标稳定为条件重新折叠，不只按固定延时或点击返回码判断成功。
5. **扩到三项并接设置。** 每项单独验证后才允许对应开关生效。覆盖正常退出、崩溃后重启、权限撤销、系统菜单进程重启、睡眠唤醒、刘海屏／外接屏、全屏、菜单栏自动隐藏和用户改动图标顺序。
6. **精确折叠不成立时换备选。** 可提供明确标为“按位置折叠”的 Ice 式模式。系统设置手动隐藏始终作为说明性兜底，不能标记为 Combo 自动折叠。

验收以**实际可见状态、原生菜单可操作、关闭后能恢复，以及未选图标不受影响**为准。失去定位、权限或恢复能力时，停止折叠并解除 Combo 自身能解除的占位／限制，向用户说明未恢复的项目；不能承诺在辅助功能被撤销后仍可自动恢复 macOS 保存的图标顺序。私有接口失败、系统版本变化或其他管理器冲突时采用同一“保留系统图标可用”的处理原则。

日期需求仍保留，但系统时钟／通知中心并非普通可移动状态项。隐藏日期文字不等于折叠整个时钟，首轮不修改时钟设置。

## feature 分支第一轮实机结果

- 在 macOS 27.0（26A428），`CGSGetProcessMenuBarWindowList` 返回两个菜单栏窗口，几何分别为 1470×33 与 1920×30，均覆盖整块显示器菜单栏；没有可供 Wi-Fi、声音、电池逐项识别的独立窗口。因此，当前机器上不执行 Thaw 式按窗口拖拽。
- MenuBarAgent 的辅助功能树可读出三项 ID：`com.apple.menuextra.wifi`、`.sound`、`.battery`。工作树应用获授权后，首版广度扫描超时，次版窗口扫描未定位；改为代理根节点的定向扫描后，三项均找到候选，`AXPress` 动作和位置属性均可读。这不是可见性、唯一性或菜单可打开的证明。
- `MBAssessmentModeConfiguration` 与 `MBAssessmentModeAssertion` 在系统中存在；独立 CLI 探针排除 Wi-Fi ID 6，激活回调返回成功，5 秒后明确 `invalidate`。回调不足以证明屏幕图标隐藏，也不足以证明原生菜单可由 Combo 唤起。
- 应用内单项 8 秒实验曾开放，带立即释放、退出释放和睡眠释放；用户实测 Combo 图标也会被折叠后，三个试验按钮已暂停。正式总开关仍禁用。后续启用前仍须满足上文稳定签名、Combo 自身可见性和原生菜单闭环条件。
- 当前构建重新授权后，三项分别做 8 秒连续采样：开始约 1.7 秒时仍在 `MenuBarAgent` 辅助功能树，第 3.1 秒起只有目标项消失，其余两项持续存在；第 7.3–7.4 秒仍保持，8 秒结束后目标项重新出现。电池实验中点击“立即恢复”后，电池项立即重新出现。
- 进一步的 15 秒隔离探针只排除 Wi‑Fi 时，Combo 与 Wi‑Fi **一起**从 `MenuBarAgent` 辅助功能树消失；放行全部系统项时两者都在，释放限制后两者恢复。给 Combo 状态项增加 `autosaveName` 的临时构建仍会同时消失。系统设置里的 Wi‑Fi、声音、电池复选框逐项关闭时，则只移除目标项；实验结束后三项都已恢复原先开启状态。详见[补充调查](macos27-menu-folding-research.md)。
- 菜单栏代理的窗口截图未提供可辨认的系统图标，故上述证据只证明辅助功能树变化，不能宣称屏幕像素的视觉验收通过。电脑操作工具直接点击 Wi-Fi 辅助功能元素没有观察到原生菜单。Combo 在已授权进程里分别对三项执行 `AXPress`，均返回成功但未观察到原生菜单；随后对 Wi-Fi 的 AX 位置 `(1245, 5)` 用完整 mouse-down/up 点击中心 `(1256, 16)`，仍未观察到原生菜单。来源项目指出隐藏项目的 AX 坐标可能滞留于上次绘制位置；本机无法从当前截图确认该图标当时实际可见，因此不能归因于点击机制失效。为防误点，已撤下坐标点击入口。临时放行、真实菜单唤起和关闭后重新限制均未实现；正式折叠继续禁用。

下一轮须先解释并解决私有方案同时隐藏 Combo 的原因，再验证逐显示器实际可见与可点击；解决前不继续接入三个开关。若图标本来已由系统设置或其他管理器隐藏，先提示用户恢复可见，不使用 AX 缓存位置猜测。
