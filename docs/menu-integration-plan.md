# Combo 系统菜单整合：已确认方案与验证计划

> 2026-09-23 路线更新：macOS 27 起优先研究 Thaw 的菜单栏折叠实现；此前 Ice／私有白名单调研保留为备用，不再按下方旧验证顺序直接实施。最新证据见 [Thaw 调研](thaw-menu-folding-research.md) 与 [备用方案调研](macos27-menu-folding-research.md)。

2026-09-22。用户已同意推荐的可选模式、两步入口和短暂露出原图标；新增电池为同级目标。此文件是实施增补，覆盖此前仅手动隐藏的建议。

## 已确认行为

- 默认关闭“整合系统菜单”；用户主动启用并授权后，折叠已选目标。Wi-Fi、声音／AirPods、电池三项初始均选中，可独立取消；关闭总开关保留选择。
- 三个系统状态项仍须存在，不在系统设置取消勾选。不存在时提示用户启用；不能声称已折叠成功。
- 左键 Combo 打开面板。Wi-Fi、输出设备、电池各行提供“打开系统菜单”入口。电池入口不随中央显示日期或耳机而消失，外圈始终为本机电量。
- 点击入口先关闭 Combo 面板，临时展开目标并唤起原生菜单。菜单关闭后归位，再折叠；不能固定延时盲目收起。
- 菜单操作由用户完成，Combo 不代选网络、不切换降噪、不更改电源模式。AirPods 实际选项由系统决定。
- 需要辅助功能权限，明确新增操作系统菜单的用途，不能沿用“只读播放器”的说明。先验证无录屏方案。
- 权限撤销、定位歧义、超时、系统重启相关组件、可见空间不足：停止本轮动作并解除自己的折叠占位，尽力恢复布局，保留系统设置入口。撤权后可能无法重新排列，不能保证原顺序完全恢复。
- 正常退出或关闭整合前解除折叠并恢复；异常退出无法保证执行恢复代码。下次启动检查恢复记录，不能盲目移动已被用户重新排列的图标。
- 不同时争用其他菜单栏管理器的图标布局；检测到冲突或无法稳定管理时暂停整合并解释原因。

独立选择必须保证未选图标可见；若无法安全分组则暂停整合。设置行为详见[设置界面规格](combo-settings.md)。

## 日期需求单独保留

用户曾提出中央选日期时也折叠日期。macOS 的日期属于时钟／通知中心入口，并非独立可随意移动的状态项。Apple 文档说明时钟始终显示，但可将日期文字设为不显示。不能把“隐藏日期文字”当成“整个时钟已折叠”。此要求保留为待验证项，不因最后一次只强调电池而丢弃，也不默认修改系统时钟设置。

依据：[macOS 26 时钟格式](https://support.apple.com/guide/mac-help/mchlb3236e90/26/mac/26)。

## 验证顺序

1. 公开 AX 接口读取 Control Center 的菜单栏项，记录 Wi-Fi、声音、电池的标识和可执行 action。诊断仅遍历菜单栏，不遍历网页或应用窗口。
2. 对单个、精确匹配且支持 AXPress 的项目执行操作。未知/重复标识拒绝执行，不用坐标猜点。
3. 用签名 GUI 原型复验步骤 1–2；终端权限结果不代表最终应用权限。
4. 再验证折叠占位、目标移动、菜单关闭检测、归位与失联恢复。公开路径不足时记录失败，不未经决定引入私有接口。
5. 在刘海屏、外接屏、全屏、自动隐藏菜单栏、不同语言和 macOS 26 小版本中验收。三个目标逐个记录结果。

## 本次最小探针

`prototypes/menu-access/MenuProbe.swift`：公共 AX 菜单项读取及显式 AXPress 探针，不包含折叠引擎，不截图，不请求定位，不自动申请辅助功能。默认只输出使用方法。`--list` 在已有权限下列举菜单项；`--press <精确标识>` 仅用于主动验证一个项目。

自动检查仅证明参数保护、目标歧义拒绝与可编译性。尚未证明真实菜单可唤起，更未证明自动折叠可发布。未授权时记录实际阻塞，不改用私有接口。

已将只读检测接入设置页，后台执行且有读取范围/时间上限；仅主动点击授权入口才提示系统授权。候选标识与可执行 action 分开报告，不因发现候选就宣称原生菜单或折叠可用。实际 GUI 检测返回需要辅助功能授权，尚未读取到本机菜单树、未执行点击与布局修改。

## 2026-09-23 macOS 27 实机结果

用户已为当前 Combo 构建授予辅助功能；应用内点击“检查菜单访问”不再进入授权页。原检测器仅扫描 `com.apple.controlcenter`，返回“未发现公开 AX 菜单栏项目”。扩大**只读**检测到 `com.apple.systemuiserver` 后，本机 GUI 结果为：

```text
控制中心：AXMenuBar = -25212，AXExtrasMenuBar = -25212，菜单项 0
系统菜单栏：AXMenuBar = -25212，AXExtrasMenuBar = -25212，菜单项 0
```

macOS 26 SDK `AXError.h` 将 -25212 定义为 `kAXErrorNoValue`（请求的值或元素不存在），不同于 `kAXErrorAPIDisabled`。这证明当前设备上的这两个公开根属性没有给出可定位菜单项；不证明系统菜单一定没有其他公开可访问路径。不能继续执行候选标识匹配、AXPress、折叠与归位。没有读其他窗口、点击原生菜单或移动图标。

下一轮若继续系统菜单方向，应先找到在 macOS 26/27 上可复验的公开菜单栏元素路径，并验证 Wi-Fi、声音、电池三项目标唯一、动作可用以及退出恢复；否则本方案维持“不可用”，不能在 UI 开启总开关。不采用私有接口或坐标猜测。
