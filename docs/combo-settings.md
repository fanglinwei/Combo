| 页面 | 当前实现 |
| --- | --- |
| 通用 | 登录启动在首行，语言立即生效；使用引导、确认后恢复动效与电量显示偏好 |
| 外观与动效 | 三种主题、深浅与跟随系统、16 个窗口内场景；独立开始/结束菜单栏演示 |
| 菜单栏与控制 | 系统图标记录/手动隐藏指引/确认恢复，Wi‑Fi 密码偏好和电量显示；系统设置按钮位于对应组标题右侧 |
| 媒体来源 | 保留现有播放卡片与来源按钮；声音设置、四种图例、可展开读取说明 |
| 实验性项目 | 折叠继续暂停，保存项目选择；用户发起只读检查，必要时说明权限并续接原任务 |

材质使用系统玻璃按钮、原生 sheet 和浮动玻璃侧栏；内容组保持稳定表面。减少透明度时侧栏回到实色，增强对比度时加强边界。音乐卡片保持原有 20pt 内距、14pt 圆角、80pt 封面和来源按钮。

新用户低电量显示开启且阈值为 20%；已有有效阈值（包括关闭值 0）保留。关闭后保存最后一次正阈值，重启再开启仍恢复原值。无效输入就地提示并保留，不保存。

系统图标基线、当前检测结果与权限分开。按设备适用项目完整读取后才记录；已有完整基线不覆盖，恢复后也保留。恢复需用户确认具体记录值，部分失败只重试失败项。退出或下次启动均不会自动恢复，也不因旧恢复标记自动打开设置。窗口关闭结束演示，演示不持久化。指引使用已有 MenuBarBefore/After 图片，可不授权直接查看；需要权限时在指引内就地解释。

验证：`./verify.sh` 构建及全部回归检查通过；新增 SettingsPreferencesCheck 覆盖新默认值、旧值迁移、跨重启开关、完整基线、不覆盖记录、单项恢复规划、窗口尺寸与关闭设置后的演示清理。RenderSettings 提供六页 × 两种窗口尺寸 × 中英文 × 六种主题外观的 144 个标准渲染，并补充 6 个较大字号环境与高对比窗口外观样本；内容区尺寸由 AppKit 根据标题栏计算。

Mac 解锁后，实际窗口已核对六页导航、玻璃侧栏与按钮、播放卡片、展开与滚动、跨页演示和结束、无效阈值输入与修正、恢复确认和权限 sheet 的 Escape 取消。只读检测的权限说明放在发起操作旁边，不叠加第二个 sheet；系统项目各自带读屏标签和值。系统“减少透明度／增强对比度／减少动态效果”的完整切换、全键盘导航、VoiceOver 实际朗读及真实授权后的记录／恢复流程仍未完成实机验收；离屏渲染不代替这些检查，也不证明所有固定字号会随系统放大。

下文保留首版规格及历史技术说明；自动折叠、原生菜单点击和来源配置方案仍属后续规划，与上述当前行为冲突时以上述说明为准。

## 1. 窗口与导航

采用独立原生设置窗口，左侧六组：通用、外观与动效、菜单栏与控制、媒体来源、实验性项目、关于与帮助。菜单栏面板保留“设置…”入口；重复打开复用已有窗口，关闭设置不退出 Combo。窗口初始 850 × 690 pt，最小 780 × 620 pt，可调整；内容区滚动，优先保证系统字号与键盘操作，不锁死像素尺寸。

普通偏好修改后立即生效，不增加“保存”按钮。涉及系统授权、登录项注册、菜单布局的操作显示处理中/失败状态，不能先画成功开关再忽略失败。预览场景不会改变真实系统状态。

面板收起规则（2026-10-03）：主面板与展开的详情属于同一组；点击外部区域、切换到其它应用或切换 Space 时收起整组，不依赖窗口取得 key。菜单栏图标的点击交给 toggle，避免先自动收起再重新打开；权限期间再次点击图标仍可主动收起。鼠标与应用/Space 监听仅在面板打开时安装，收起或退出时移除。

定位、蓝牙和系统 Wi‑Fi 钥匙串读取按请求等待状态阻止自动收起；本地网络缺少统一授权完成 API，额外根据可见的 UserNotificationCenter / SecurityAgent / CoreServicesUIAgent 系统窗口保护，不读取标题或截图，也不请求辅助功能或录屏权限。系统代理窗口识别属于保守判断，其他系统版本/授权宿主仍需实机复核。权限允许或拒绝后保留面板，恢复监听，不补执行等待期间忽略的点击；下一次外部点击正常关闭，授权返回原应用也不算新切换。

## 2. 通用

| 功能 | 控件与默认值 | 行为 |
| --- | --- | --- |
| 登录时启动 Combo | 开关，默认关闭 | 用户主动开启；显示系统实际注册状态及失败原因 |
| 恢复显示偏好 | 按钮，需确认 | 仅恢复播放动效开启、低电量显示开启且阈值为 20%；不改登录项、媒体来源、系统权限或图标布局 |
| 退出 Combo | 按钮 | 结束应用运行；不自动恢复系统图标 |

为避免“恢复默认”范围不清，按钮使用“恢复显示偏好”，确认文案列出具体两项。恢复系统图标另有专用按钮。

登录项使用 ServiceManagement 的 `SMAppService.mainApp` 注册/注销。界面根据真实 status 显示已开启、已关闭、需要系统批准或操作失败；应用重新激活时刷新，处理用户在系统设置中关闭登录项的情况。失败不只修改 UserDefaults 假装成功。不新增 daemon、管理员 helper 或循环自启动行为。

参考：[mainApp](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp)、[register](https://developer.apple.com/documentation/servicemanagement/smappservice/register())。最终通过签名应用实测首次启用、拒绝、系统关闭及应用移动后的行为。

## 3. 外观与动效

| 功能 | 控件 | 默认与说明 |
| --- | --- | --- |
| 中央内容 | 自动显示，无设置控件 | 按网络、电量、静音及当前默认输出设备类型自动选择；不显示日期 |
| 播放时显示音柱 | 开关 | 默认开启；固定动画，不采集音频 |
| 减少动态效果 | 只读状态与说明 | 跟随系统，生效时显示静态音柱；不另造冲突开关 |
| 效果预览 | 放大图标＋约 22 pt 实际尺寸 | 标记“示例”，不与真实状态混淆 |
| 预览场景 | Wi-Fi/有线/播放/静音/充电 | 临时选择，不持久化、不触发真实播放或系统操作 |

外圈始终表示 MacBook 本机电量。已移除日期与设备切换事件提示；保留耳机演示，旧版中央选择偏好不再读取。

提供蓝色、紫色、暖金色三种主题；不提供圆弧粗细、动画速度、圆点数量、自定义曲线或完整时间显示。

### 3.1 中央状态优先级（2026-09-24）

设置预览与菜单栏使用同一套中央内容选择和动画规则；外圈电量、底部音量／播放仍独立更新。

Wi-Fi 正常使用两道圆头弧线与圆点；Wi-Fi 已关闭且没有可用网络路径时使用斜杠图标，属于 P2。有线网络可用时继续显示有线常驻内容。Wi-Fi 开启但无可用路径时显示 Wi-Fi 加感叹号，状态未知仍显示短横线。

| 等级 | 状态 | 结束条件 |
| --- | --- | --- |
| P4，最高 | 电源实际拔插 | 中央使用 C 方案线条插头：插入带圆形对勾，拔出带圆形 X，不显示电量数字；缩小完成后保持 5 秒，再恢复最新常驻状态；新事件覆盖旧事件，不补播 |
| P4 | 调整音量或切换静音，中央显示 0–100 纯数字，静音显示 0 | 不依赖媒体播放；正常尺寸短淡变，最后一次调整后 2 秒结束；连续调整续期，不重播入场；与电源提示互相覆盖，不补播 |
| P3 | Wi-Fi 正在连接 | 连接成功、失败或取消；被 P4 覆盖后仅在仍连接时恢复 |
| P2 | 网络异常／未知／关闭、优先电量、AirPods 耳机、兜底电量 | 按最新状态选择 |
| P1，最低 | Wi-Fi 正常 | 按最新状态选择 |

常驻选择顺序：网络异常／未知／关闭 → 电量优先条件 → 当前音频输出为蓝牙或 AirPlay 设备 → 正常 Wi-Fi → 电量百分比。充电且电量有效、或低于用户阈值时优先显示电量。暂停播放不移除当前设备符号；切回扬声器恢复其他常驻内容，仅蓝牙连接不触发耳机常驻。

设备识别只以默认输出的 CoreAudio transport 为入口。蓝牙／BLE 先看 AirPods/Beats 品牌名，再看非 0 CoD，最后通用名称关键词或 unknown；CoD 是自报弱信号，不能承诺精确分类。既有 helper 在蓝牙已授权、真实 live 面板活动时复用 status 读取当前已连接设备的 CoD，核对设备 ID 与 UID token；普通蓝牙一次，当前 AirPods 复用每 3 秒状态更新。没有产品 ID 表或 `system_profiler` 轮询，改名 AirPods 无型号信号时仍可能显示通用耳机。

AirPlay 的 `modelID` 前缀 `AppleTV*` → `appletv`、`AudioAccessory5*` → `homepod.mini`、其它 `AudioAccessory*` → `homepod`，未知或失败 → `airplay.audio`；已校验路由可显示 `客厅（AirPlay）` 等真实名称。helper 调用 `--route <deviceID> <UID SHA256>`，短进程 2 秒超时，核对 deviceID/UID/context/endpointID；Request 带 UUID 序号，新请求取消旧进程，无输出或离开 AirPlay 清缓存，唤醒先失效再读。失败退回 CoreAudio 名及通用符号，面板可手动重新读取。`canSetVolume` 缺失表示未知；Apple TV false 提示“电视音量请用遥控器”，Mac 软件输出音量不等于接收端硬件音量。

附近 AirPlay 设备首次按“查找”才开始浏览 `_airplay._tcp` 并保存 opt-in；此后仅真实 live 面板可见且屏幕活动时自动恢复，关闭/演示/睡眠停止。发现状态为 idle/searching/ready（含空结果）/denied/failed；仅 `DNSPolicyDenied` 显示本地网络权限不足与设置入口，普通网络故障可重试。首次请求记录 askedAt，浏览器 ready 或停止后清除；仅应用切换在系统弹窗出现前有一秒交接保护，弹窗可见期间按系统授权窗口保护，真实弹窗仍需实机验证。列表由发现设备和当前路由动态推导，切离 AirPlay 后立即恢复附近项；未连接项点按打开系统声音设置，不承诺应用内建立全系统路由。仅 `_raop._tcp` 的 AirPlay 1 设备尚未覆盖。

中央与输出列表共用分类结果，其他传输类型不显示中央设备符号。固定 16 个 SF Symbol 原图缓存，颜色每次应用，未知名不缓存。HomePod、多设备、macOS 26、蓝牙 CoD 与新权限/生命周期流程未完成实机回归，历史 Apple TV 采集不能替代本轮验证。

系统静音或音量为零时底部显示静音；调整音量或静音触发的中央 P4 显示 0，取消静音显示恢复后的音量。P4 结束后按最新状态恢复：Wi-Fi 仍连接中则显示 P3，否则显示常驻内容。电量未知且无其他常驻内容时显示“—”。

一般状态升优先级和同级不同状态切换播放动画；降级立即替换中央图标，包括 P2 常驻内容恢复到 Wi-Fi 正常 P1。音量提示使用正常尺寸短淡变，网络内部切换使用下面的专用时序。电量数字、音量数字等数据更新不重播入场。减少动态效果仍遵循系统偏好。预览保留 AirPods 播放、Wi-Fi 连接中、Wi-Fi 静音、电源插拔及 Wi-Fi 已关闭，共 16 个场景；临时场景会自动回到有效的常驻内容。

电源提示在入场后第 4.2 秒完成缩小，从此开始保持 5 秒，第 9.2 秒恢复常驻状态；电量环在这 5 秒的前 0.5 秒填充，不另加等待。减少动态效果时使用 0.16 秒淡变，随后保持 5 秒。音量提示在普通与减少动态效果模式下均使用 0.16 秒正常尺寸淡变，最后调整后总计 2 秒结束，不额外叠加入场时长。底部音量调整标记同样按最后调整后 2 秒恢复播放显示。电源提示只由供电来源变化触发；满电停充、充电上限暂停及恢复充电均不触发插拔提示，常驻电量数字保留。

网络动画时序（按用户录屏的分解／重组与逐层亮度变化实现）：

- 先放大中央并收起外围；在放大状态下完成约 0.4 秒的切换，完成后保持 2 秒，再缩小并恢复底部和电量环；缩小完成后保留结果 5 秒，再切回最新常驻状态。
- 连接中保持中央放大、外圈和底部隐藏，圆点与两道弧线由内向外交替变亮，持续到真实过程结束，不按固定动画时长退出。
- 连接成功先完成 Wi-Fi 收尾，再等待 2 秒；失败或关闭 Wi-Fi 分别切到异常／斜杠结果后等待 2 秒。有线可用时恢复有线内容。
- 已放大的图标直接进入下一段，不先缩小。网络内部的 P3 → P2／P1 是降级直切规则的例外。
- 被 P4 覆盖后，若仍在连接则直接恢复放大的 loading；若连接已在后台结束，则直接恢复最新常驻内容，不补播成功动画。被打断的成功停留作废。
- 减少动态效果下使用短淡变与静态连接图形，不做空间放大或亮度循环；结果淡变完成后同样保持 5 秒。预览可依次点击“Wi-Fi 已关闭 → Wi-Fi 正在连接 → 无线正常”验证完整流程；持续选择连接中可验证长时间等待。

当前接入范围：电源和默认输出设备事件来自系统；设备图标使用共享分类结果与公开 SF Symbols，缺失符号退回 `headphones`。名称只是分类提示，不能保证具体型号。Wi-Fi 的连接过程来自 Combo 发起的连接操作，扫描不算连接；系统开关与链路事件会刷新关闭／异常图标。真实媒体检测使用隔离 helper 读取系统注册媒体客户端；示例场景仍不代表真实播放状态。

## 4. 菜单栏与控制

Wi‑Fi 卡片提供“使用系统保存的 Wi‑Fi 密码”开关（默认开启，以 `wifiUseSystemPasswords` 持久化）及可展开的“密码与隐私说明”入口。仅在用户点击已知的普通加密网络时按需请求对应密码；开关不表示系统已授权。拒绝或取消后停止本次连接，并在本次运行中暂停再请求，用户可在该入口点击“允许下次请求授权”。关闭开关会使尚未完成的读取结果失效，但不会撤销 macOS 已记录的项目访问权限。

隐私文案明确：仅为 Wi‑Fi 切换读取所选网络的密码，不读取其他钥匙串项目，不另存系统密码，不上传网络名称或密码。不授权时提供手动输入；“连接成功后在本机记住密码”默认勾选，用户可取消。保存位置是本机 Combo 钥匙串项目，失败连接不保存；已有 Combo 密码可在连接表单中删除。不要宣称“不读取任何数据”或全局“已授权”。

电量显示组提供“电池详情的高耗能应用”：菜单选择最多 1 / 2 / 3 个，默认 1，立即生效，以 `energyAppLimit` 持久化。数量是上限，不保证补足。主面板显示加载、正常空名单、应用列表或获取失败四种状态。接口与系统版本支持范围见 [系统高耗能应用研究](system-energy-apps-research.md)。

主面板“个人热点”展示真实手机名称、四阶蜂窝信号条及电池轮廓内居中的电量整数（不带百分号，内部填充随电量变化）；未确认的网络制式隐藏。点击手机或右侧设置箭头打开系统 Wi-Fi 设置，由用户连接。空列表显示“未发现可用个人热点”，读取失败显示“暂时无法读取手机信息”及重试入口。打开面板时读取，关闭面板、屏幕休眠或 Wi-Fi 关闭时停止；目前私有发现能力仅支持已验证的 macOS build `26A428`。详见 [个人热点接入记录](mobile-hotspot-api-feasibility.md)。

### 4.1 自动折叠历史方案（未启用）

- 总开关“整合系统菜单”默认关闭。
- Wi-Fi、声音／AirPods、电池独立复选，初始均选中。总开关关闭时允许预选，但不进行系统操作。
- 关闭总开关：停止整合并恢复已管理图标，保留三项选择便于下次启用。
- 取消单项：仅恢复这一项，其余仍管理；恢复有歧义时暂停整合，不挤压或误藏未选择图标。
- 全部取消时不折叠任何项目，提示“选择至少一个项目”；不因三个选项为空隐式修改别的设置。
- 在占位分区实现中，独立选择需要先将选中项与保留项正确分组。独立管理能否可靠实现属于发布门槛，不是复选框本身能保证的能力。

每项状态：未启用、需要授权、系统图标未启用、正在处理、已折叠、暂不可用。只有实际验证过布局才显示“已折叠”。不支持版本不展示可用假开关。

### 4.2 自动折叠历史操作方案（未启用）

| 操作 | 行为 |
| --- | --- |
| 前往辅助功能设置 | 用户主动触发，说明 Combo 会排列并打开所选系统菜单 |
| 查看启用系统图标指引 | 提醒在 macOS 保留对应菜单栏项，不能先取消系统显示 |
| 测试打开 | 针对一项转交原生菜单，不修改菜单选项；仅在权限/定位满足时可用 |
| 显示系统图标并停止折叠 | 关闭总开关并解除 Combo 占位，尽力恢复；保留各项选择，不重置系统控制中心 |
| 查看恢复帮助 | 在权限撤销、外部管理器冲突或归位失败时说明手动恢复路径 |

测试 action 成功不等于用户看到正确菜单，不能单凭 API 返回值标注整套功能测试通过。菜单尚未关闭时不自动收起。

辅助功能是授予 Combo 的同一系统权限，独立开关控制的是功能用途，不是系统提供三个独立权限。关闭此模块也不撤销媒体适配仍使用的授权。

日期折叠继续作为待验证需求记录；首版此页不提供可用日期折叠开关，不通过自动修改时钟日期格式冒充完成。

完整故障与恢复要求见 [系统菜单整合计划](menu-integration-plan.md)。

## 5. 媒体来源

这一页只回答三件事：**现在在播什么、菜单栏会变成什么样、状态是怎么读到的**。先前用四行静态文字冒充的“来源列表”已删除：它们不反映任何状态，只是一张特性表，且其中 QQ 音乐在本机并未安装。

**当前在播。** 一条实时状态——正在播放／已暂停／重新连接中／未检测到播放——加封面、曲名、歌手与来源 App 的真实图标；系统能定位到该 App 时提供“打开”。空闲时说明原因：Combo 只显示向系统报告播放状态的应用。

**菜单栏会怎么变。** 四格对照，用 IconRenderer 渲染的四个真实状态：正在播放、已暂停、AirPods 播放、AirPods 已连接；当前状态那一格用强调色标题指认。“在菜单栏演示播放”留在这一节。被对照图换下去的两条规则（系统静音优先于播放、开启减少动态效果时不循环）保留为图例下一行说明。

**怎么读到的。** 读取：只读系统播放状态，不采集声音、不录音、不读网页内容。识别：未向系统报告播放状态的播放器不会出现在这里。保留：曲目信息在播放结束后保留约 5 秒，切歌时不会闪空。

每个来源单独的启用开关、连接状态与授权指引**移入后续版本**：Safari／Chrome 需要配套扩展，网易云音乐／QQ 音乐需要逐个验证辅助功能适配。能力验证通过前，正式发行界面不提供无法使用的开关；相关门槛见[后续版本规划](combo-roadmap.md)。页面用应用自己的示例场景（`Snapshot.demo`）显示状态图例，示例数据不改变系统状态，也不声称已检测到其他应用的播放。

网页内容、歌名、截图不纳入诊断。

## 6. 关于与帮助

- 显示产品版本与构建号。
- 列明 MacBook、macOS 26+ 和实际通过验证的播放器/浏览器版本范围。
- 权限说明：菜单整合与桌面播放器使用辅助功能的各自用途；浏览器网站访问用途。
- 帮助入口：图标含义、动效规则、来源配置、系统图标恢复。
- 简单诊断：来源类型、连接状态、错误原因、最近状态更新时间；用户主动刷新，不默认上传，不显示网络名/网址/媒体标题。

首版不增加账号、云同步、自动更新服务、外部设备电池设置或任意诊断命令入口。

## 7. 状态、持久化与可访问性

普通偏好使用 UserDefaults：电池显示阈值、动效开关、整合用户意愿、三项目标集合。登录项与辅助功能实际状态实时读取系统；浏览器连接状态来自桥接，不把缓存当授权真相。

整合启用意愿与实际运行状态分开。下次启动可以恢复已确认的用户意愿，但只有权限、目标和布局检查通过后才折叠；失败时显示暂停原因。布局恢复记录与普通设置分开保存，不能被“恢复显示偏好”清空。

控件使用原生标签、键盘焦点与 VoiceOver 描述；状态不只靠颜色。处理期间禁用重复提交，同一操作完成后恢复焦点。实时预览每帧变化不触发读屏播报。窗口关闭不停止已经启用的功能。

## 8. 验收清单

- 首次启动：登录时启动关闭、整合关闭、三项预选、中央自动显示、动效开启；没有主动权限弹窗。
- 设置中没有中央内容选择；旧版日期/输出设备偏好不影响自动显示，中央按当前默认蓝牙/AirPlay 输出分类，设备切换不产生 P4 事件提示。
- AirPlay 查找首次需用户操作，关闭/演示/睡眠停止；权限拒绝与普通网络错误区分、失焦保护、旧回调与路由身份校验由自动化覆盖，真实权限与硬件行为另做实机验收。
- 总开关关闭时预选不移动图标；三项每种组合不误藏未选择项目。
- 总开关关闭、单项取消、正常退出和权限撤销各走对应恢复路径。
- 系统拒绝登录项注册时显示失败/待批准，不画成已开启；系统外部更改后状态刷新。
- 关闭动效不误撤销系统权限；空闲时说明为什么没有来源，不把未接入的来源画成已支持。
- 恢复显示偏好不改媒体、登录项、权限和菜单布局。
- 重复打开只有一个设置窗口；键盘与读屏可完成设置；未验证能力不伪装可用。
